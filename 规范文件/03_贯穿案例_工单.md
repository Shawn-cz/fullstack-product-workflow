# 贯穿案例：内部工单提交与处理

版本：1.3.0｜性质：纯示例设计，所有业务选择和数值均为假设；没有真实访谈、代码实现、用户试用、测试通过或发布记录。文末附带机器契约片段、React + Preline 组件示例、带 `@req/@ac` 标签的先行测试样本与 T07/T12 指纹证据表填写范本，供零经验成员直观对照交付颗粒度。

目的：展示同一个需求怎样连接业务规则、数据、API、组件、任务和验收。实际项目不能把这些假设直接当作已获批准的业务决定。

## S0：项目卡

- 场景：成员提交内部问题，处理员查看并关闭工单。
- 本轮范围：创建、列表、详情、关闭；排除附件、评论、通知、审批、搜索和重新打开。
- 平台：内部 Web；假设已有可信登录服务，本轮不自行开发认证系统。
- 执行方式：一位团队成员借助 AI 从 S0 连续推进到 S9，完成需求、契约和界面设计，推进实施准备与验证。下文 MEMBER/HANDLER 是软件用户权限类型，不是团队岗位。
- 路径：新功能完整设计，但只细化上述闭环。
- 技术栈（按 STD-ARC-09 默认继承团队黄金技术栈）：前端 **React 18/19 + TypeScript (strict) + Vite + Tailwind CSS + Preline UI + Zustand/TanStack Query**；后端 **Node.js + Hono/Fastify + TypeScript + Zod**（继承 `contracts/` 通用契约包）；数据库 **Prisma ORM + PostgreSQL 16**（本地 `ci/docker-compose.postgres.yml` 与 CI/生产同构，**禁用 SQLite**）。无需重复编写框架对比 ADR。
- 交付终点：本案例只提供设计和验证计划（附格式填写范本），不执行真实部署。

## S2–S3：需求、规则和状态

| 需求 | 内容 | 结构化验收条件（AC-xxx，用于测试先行 RED→GREEN 闭环） |
|---|---|---|
| REQ-001 | 成员创建工单 | `AC-001`：MEMBER 提交有效标题/描述与 UUID，返回 201 统一信封，PostgreSQL 新增 1 条 `OPEN` 记录；<br>`AC-002`：同 `requestId` 同载荷指纹重放返回原创建快照；同 `requestId` 不同载荷指纹返回 `409 IDEMPOTENCY_FINGERPRINT_MISMATCH` |
| REQ-002 | 按权限查看列表和详情 | `AC-003`：MEMBER 请求他人 `ticketId` 时接口返回 `404 NOT_FOUND`，且本人列表不包含他人记录；<br>`AC-004`：HANDLER 查看全部列表并按 `createdAt` 降序分页 |
| REQ-003 | 处理员关闭工单 | `AC-005`：HANDLER 带正确 `expectedVersion` 与说明关闭 `OPEN` 工单，更新为 `DONE` 且审计同事务入库；<br>`AC-006`：MEMBER 调用关闭返回 `403 FORBIDDEN`；两处理员并发关闭同一版本仅一成功、另一返回 `409 CONFLICT_VERSION` |

以下规则正文为本案例权威位置；接口和测试引用编号。

| 规则 | 具体约定 |
|---|---|
| RULE-001 | MEMBER 可以创建和查看自己工单；HANDLER 可以查看全部及关闭工单。未授予的动作拒绝；HANDLER 不自动继承创建权限 |
| RULE-002 | 标题去首尾空白后 1–100 个 Unicode 码点；描述 1–2000 个码点；关闭说明 1–1000 个码点。仅纯文本，按纯文本显示 |
| RULE-003 | 状态仅 OPEN → DONE；关闭须满足角色、当前状态和版本一致；DONE 本轮不可重新打开 |
| RULE-004 | 创建使用调用者作用域内的 requestId 去重；相同 ID 和相同规范化输入重放原创建结果；相同 ID 不同输入报冲突 |
| RULE-005 | 关闭成功将状态、说明、关闭人、关闭时间及版本一次性更新，并记录审计；失败不产生半更新 |
| RULE-006 | 成员请求不属于自己的工单与不存在工单统一返回不可见；服务端执行，不依赖前端过滤 |

规则来源：上述均为示例设定。真实项目需把其依据、决定人和日期补到 T04。

| 当前状态 | 动作 | 权限/条件 | 下一状态 | 失败 |
|---|---|---|---|---|
| 尚无记录 | 创建 | MEMBER、输入有效、去重检查 | OPEN，version=1 | 校验/身份失败不创建；重放不创建 |
| OPEN | 关闭 | HANDLER、expectedVersion 与当前一致、说明有效 | DONE，version 加 1 | 状态或版本冲突保持原记录 |
| DONE | 关闭 | 本轮不允许再次关闭 | DONE | 409，客户端重新查询并显示现状 |

恢复：创建超时复用同一 requestId 重试；关闭超时先查询工单，若已 DONE 显示最新事实，不能自动宣称本次关闭成功。若仍 OPEN，可基于最新状态让用户重试。误关闭的重新打开需求不在本轮，是否接受此限制是上线前必须确认的业务决定。

## S4：技术与数据

模块：页面/组件 → 客户端工单服务 → 服务端工单业务入口 → 数据访问。授权和状态规则在服务端。一个服务内的普通事务足以满足本案例，暂无微服务、消息队列或分布式补偿需求。

数据对象 DATA-001 Ticket：

| 字段 | 类型与约束 | 来源 |
|---|---|---|
| id | 服务端生成的不透明字符串、唯一 | 服务端 |
| creatorId | 非空，禁止由请求体指定 | 已验证身份 |
| requestId | UUID；与 creatorId 组成唯一约束 | 客户端在一次创建意图开始时生成 |
| title / description | 纯文本，按 RULE-002 规范化与校验 | 输入 |
| status / version | OPEN 或 DONE；正整数 | 服务端 |
| createdAt / closedAt | 服务端 UTC 时间；未关闭时 closedAt=null | 服务端 |
| resolution / closedBy | OPEN 时为空；DONE 时非空 | 关闭说明/已验证身份 |

DATA-002 创建去重记录：调用者、requestId、规范化输入摘要、原始成功响应，与工单创建同事务持久化。案例选择保留到工单被删除，以保证该记录存续期间的重放；删除后不再承诺历史重放。工单保留期限尚待实际组织确定；本例不提供删除接口。

DATA-003 审计记录：动作、工单 ID、执行者、时间、变更前后状态与版本、操作关联 ID。工单内容不复制进审计。审计访问、保留期限由真实项目确认，未确认前仅可进行合成数据试验。

创建并发：数据库唯一约束兜底；冲突时读取已有去重记录，比较输入，返回重放或 409，不能“先查没有再插入”作为唯一防重复措施。

关闭并发：更新条件同时包含 id、status=OPEN 和 expectedVersion；受影响行为必须在事务内正确区分不存在、冲突与成功；审计与工单更新同事务。version 不是权限依据。

### API 契约摘要

这是人工阅读摘要，尚未提供机器可读 OpenAPI。真正实施前按 STD-API-01 补完整 Schema 并校验示例，不能宣称契约自动验证已完成。

所有接口先验证登录身份；默认不允许。没有把凭据放到 URL 或本文档。统一错误结构：`code`、可公开的 `message`、操作关联 `requestTraceId`。请求 UUID 与日志追踪 ID 是不同概念。

| 接口 | 请求 | 权限与结果 |
|---|---|---|
| API-001 POST /tickets | requestId、title、description | MEMBER；成功 201 返回 id/status/version/createdAt；重放返回同一原始响应；不同输入冲突 409；校验 422 |
| API-002 GET /tickets/{id} | 路径 id | 按 RULE-001/006；成功 200 返回有权查看的详情；无记录或无查看权 404 |
| API-003 GET /tickets | page 从 1 起、pageSize 1–50，默认 20 | 服务端先限制可见范围；createdAt 降序、id 作同时间次排序；返回 items/total/page/pageSize；无结果为 200 空列表 |
| API-004 POST /tickets/{id}/close | expectedVersion、resolution | HANDLER；200 返回最新详情；不存在 404；状态/版本冲突 409；校验 422 |

通用错误：未登录 401；无动作权限 403；服务暂不可用 503（不泄漏堆栈，客户端不盲目重试写入）。API-001 重放的是原创建快照，工单后来可能已关闭，客户端需要当前状态时调用 API-002。

#### 附：机器可读契约片段范本（PostgreSQL Prisma 模型 + 通用契约包继承，对照 STD-API-07/08）

> **说明：** 以下为黄金技术栈下“单一权威契约源”的格式示范。零经验成员无需手写此代码，由 AI 基于 `规范文件/contracts/base-contract.schema.ts` 生成后，成员对照上表核对字段名称、长度限制（1–100 / 1–2000）、PostgreSQL 唯一约束与载荷指纹规则。

```prisma
// prisma/schema.prisma（PostgreSQL 数据库持久化契约范本，严禁使用 sqlite）
datasource db {
  provider = "postgresql"
  url      = env("DATABASE_URL")
}

model Ticket {
  id          String    @id @default(cuid())
  creatorId   String
  requestId   String
  title       String
  description String
  status      String    @default("OPEN") // "OPEN" | "DONE"
  version     Int       @default(1)
  createdAt   DateTime  @default(now())
  closedAt    DateTime?
  resolution  String?
  closedBy    String?

  @@unique([creatorId, requestId])
}

model TicketIdempotency {
  id                 String   @id @default(cuid())
  creatorId          String
  requestId          String
  payloadFingerprint String   // 规范化请求体 SHA-256 指纹 (STD-API-08)
  responseSnapshot   Json     // 原始成功响应 JSON 快照
  createdAt          DateTime @default(now())

  @@unique([creatorId, requestId]) // 数据库唯一约束兜底防并发重复创建（RULE-004）
}
```

## S5：交互与组件

视觉方向示意：若嵌入既有内部系统，默认继承其导航、字体、间距、表单和状态组件；先取得实际页面与变量再定值。本案例未读取真实产品界面，不虚构颜色或组件库。用户明确指定改版或另一组件库时，按指定范围更新 T06，并验证相邻界面、主题/全局样式和交互影响。实现时按 STD-QA-10 补实际视觉证据，当前未渲染。

UI-001：工单列表及创建表单；UI-002：详情及处理员关闭操作。没有权限时不展示操作入口，但接口仍独立拒绝越权。

| 组件 | 输入/事件 | 状态归属与复用 |
|---|---|---|
| COMP-001 TicketForm | submitting、serverError；发出 submit({title,description}) | 表单管理输入；页面/业务逻辑管理请求生命周期；不含授权和数据库逻辑 |
| COMP-002 TicketStatus | status | 只显示状态，文字与颜色并用，不只靠颜色表达 |
| COMP-003 TicketList | items、loading、error、分页信息；发出选择/翻页/重试 | 请求由页面管理；状态展示可复用 |

一次有效提交开始时生成 requestId，双击期间禁用提交；超时后保留同一 ID 和输入以便重试。用户明确修改内容后作为新提交意图，生成新 ID；如果前次结果未知，先帮助查询并明确提示潜在重复，不假装禁用按钮已经解决服务端幂等。

| 场景 | 界面反馈 | 恢复 |
|---|---|---|
| 首次无工单 | 显示空状态和创建入口 | 开始填写 |
| 列表加载 | 加载提示，避免把旧用户数据作为当前用户数据显示 | 失败可重试 |
| 输入不合法 | 关联字段错误，可通过键盘定位 | 保留输入 |
| 创建超时 | “结果尚未确认”，保留输入和 requestId | 同 ID 重试或查结果 |
| 关闭冲突 | 解释工单已变化 | 重新获取详情，不覆盖别人的结果 |
| 登录失效 | 说明需重新登录；按数据敏感度设计输入保留 | 恢复身份后重新检查权限 |

原型验证任务：成员提交一个问题并找到结果；成员尝试访问另一个成员的工单；处理员关闭一条工单；模拟网络失败后恢复。尚未招募用户、未制作可交互原型、未执行。

#### 附：React + Tailwind + Preline UI 组件规范片段范本（对照 STD-REACT-01~04）

```tsx
// src/components/TicketForm.tsx（范本：单向数据流 + Preline 表单样式，不含后端数据库逻辑）
import { useState, type FormEvent } from 'react'

interface TicketFormProps {
  submitting: boolean
  serverError: string | null
  onSubmit: (payload: { title: string; description: string }) => Promise<void>
}

export function TicketForm({ submitting, serverError, onSubmit }: TicketFormProps) {
  const [title, setTitle] = useState('')
  const [description, setDescription] = useState('')

  const handleSubmit = async (e: FormEvent) => {
    e.preventDefault()
    if (submitting) return
    await onSubmit({ title: title.trim(), description: description.trim() })
  }

  return (
    <form onSubmit={handleSubmit} className="space-y-4 bg-white border border-gray-200 rounded-xl p-5 shadow-2xs">
      {serverError && (
        <div role="alert" className="bg-red-50 border border-red-200 text-sm text-red-800 rounded-lg p-3">
          {serverError}
        </div>
      )}
      <div>
        <label htmlFor="ticket-title" className="block text-sm font-medium mb-2 text-gray-800">
          工单标题（1–100 字符）
        </label>
        <input
          id="ticket-title"
          value={title}
          onChange={(e) => setTitle(e.target.value)}
          className="py-2.5 px-3 block w-full border-gray-200 rounded-lg text-sm focus:border-blue-500 focus:ring-blue-500"
          required
          maxLength={100}
        />
      </div>
      <button
        type="submit"
        disabled={submitting}
        className="py-2.5 px-4 inline-flex items-center gap-x-2 text-sm font-medium rounded-lg border border-transparent bg-blue-600 text-white hover:bg-blue-700 disabled:opacity-50"
      >
        {submitting ? '提交中...' : '提交工单'}
      </button>
    </form>
  )
}
```
