# 文件上传安全与异步定时任务幂等专项基线 (`storage-jobs-baseline.md`)

版本：1.1.0｜对应规则：`STD-DAT-05`、`STD-SEC-02`、`STD-BIZ-04`（仅在业务涉及文件上传/导出或异步定时任务时按需启用）

---

## 一、 文件上传与对象存储安全基线（S3 / 阿里云 OSS / MinIO）

零经验团队做图片、PDF、表格上传时，严禁把文件直接存进应用容器本地磁盘（容器重启即丢失且易被路径穿越攻击）。须遵循以下 6 条红线：

1. **采用对象存储 + 服务端短效预签名直传（Presigned URL）**：
   - 前端先向服务端申请上传凭证（携带声明的 `mimeType`、`sizeBytes`、`sha256` 校验和）；
   - 服务端鉴权后签发 5–15 分钟有效的单次上传 URL，前端直传对象存储，不经 Node.js 内存扛大文件流量。
2. **MIME 白名单 + 文件魔数（Magic Bytes）双重校验**：
   - 严禁仅凭 `.jpg` / `.pdf` 后缀名放行；须限制允许的 MIME 与最大字节数（例如头像 ≤ 5MB、业务附件 ≤ 20MB），高风险文件在回调确认前核对魔数字节头；禁止直接对外以 `text/html` 或 `image/svg+xml` 内联渲染用户上传文件（防存储型 XSS）。
3. **随机重命名对象键（防路径穿越与覆盖）**：
   - 对象存储 Key 必须由服务端生成，格式如 `uploads/{tenantOrModule}/{YYYY}/{MM}/{uuid}.{safeExt}`；原始文件名仅作为元数据存库展示，禁止拼接进路径。
4. **私有桶隔离 + 鉴权后签发短效下载链接**：
   - 除明确公开的营销图/头像外，所有业务附件存放在**私有桶（Private Bucket）**；下载前由服务端走三层 RBAC 校验归属（`STD-SEC-05`），通过后再签发 1–5 分钟有效的临时签名下载链接。
5. **孤儿文件与删除清理**：
   - 上传记录先落库为 `PENDING`，回调确认关联业务对象后转为 `COMMITTED`；配置对象存储生命周期规则自动清理超过 24 小时未确认的 `PENDING` 临时文件。
6. **黑盒验真必测负向场景**：
   - 将 `.exe` 或 `.html` 改名为 `.png` 上传 → 必须拦截并返回 `422 VALIDATION_FAILED`；
   - 超出大小限制上传 → 拒绝；
   - `member_B` 尝试获取 `member_A` 私有附件下载链接 → 返回 `404 NOT_FOUND`。

## 二、 异步后台任务与定时任务（Cron / Queue）幂等基线

涉及批量导出、邮件/消息发送、定时对账、状态超时关闭等后台任务时，严禁裸写 `setInterval` 无锁跑库（多容器部署会重复扣款/发双份消息）。须遵守以下 5 条设计：

1. **任务状态表与唯一防重入键（`jobKey`）**：
   - 在 PostgreSQL 建立任务记录表（如 `BackgroundJob`），每个业务调度周期生成确定性唯一键 `jobKey`（例如 `daily_close_check:2026-11-26` 或 `export_ticket:{actorId}:{requestId}`），通过数据库 `@@unique([jobKey])` 兜底防止重复入队。
2. **原子抢占与租约超时（`lockedUntil`）**：
   - Worker 领取任务时用单条条件更新原子加锁（`status = PENDING` 或 `status = RUNNING AND lockedUntil < NOW()`），同时写入 `lockedUntil = NOW() + 5m`；防止进程崩溃导致任务永久卡死。
3. **有限指数退避重试与死信告警（DLQ）**：
   - 明确 `maxAttempts`（如 3–5 次）与退避间隔（如 30s / 2m / 10m）；达到上限转入 `DEAD_LETTER` 终态并触发结构化日志告警（带 `errorFingerprint`，见 `STD-OPS-08`），**禁止无限死循环重试**。
4. **执行体自身必须可重入幂等**：
   - 即使同一任务因网络抖动在租约超时后被二次执行，业务状态更新与外部副作用也须带乐观锁或幂等键，保证最终只产生 1 次业务效果。
5. **黑盒与集成验真必测场景**：
   - 两个 Worker 同时抢占同一 `jobKey` → 仅 1 个执行成功；
   - 模拟外部依赖连续失败超 `maxAttempts` → 状态转为 `DEAD_LETTER` 且告警日志可查，不卡死队列。
