# 工作流审计与修订报告（面向零开发经验全栈团队）

版本：0.8.0｜日期：2026-11-16｜审计对象：0.7.0 工作流交付包及本次 0.8.0 升级实现。

## 1. 审计结论与背景

0.7.0 版本在**文档结构完整性、单一事实来源（SSOT）分层、防 AI 幻觉及防“虚假完成”纪律**上已具备很高的工程水准（22 个文件 SHA-256 100% 匹配，0 断链，109 条规则编号唯一）。

但结合团队真实背景——**“团队成员完全没有开发工作经验，需要开展产品设计与全栈开发工作”**——原 0.7.0 存在 **6 项关键落地断层**（如要求零代码背景成员自己审查底层代码差异、允许每个项目自由做技术栈选型、缺少本地 Git 快照救生、单模板文件过大且未封装 Skill 等）。本轮已在 **0.8.0** 中通过新增 3 条核心规则（`STD-ARC-09`、`STD-CODE-11`、`STD-QA-12`）、修订 3 条规则、补齐案例 Schema/证据范本、拆分 13 个独立模板及封装 `.agents/skills/` 完成闭环整改。

## 2. 审计发现与 0.8.0 整改闭环对照表

修订前 0.7.0 原文件包已归档至 `../历史归档_勿喂给AI/2026-11-14_至_2026-11-16/v0.7.0-baseline.zip`。

## 3. 文档场景推演复核（0.8.0）

| 推演场景 | 0.8.0 导向的执行路径 | 核对位置 | 结果 |
|---|---|---|---|
| 负责人下达明确内部工具任务，成员无外部用户可访谈 | S0 标记“指令契约型需求”，登记负责人 `DEC-001` 直接进入 S2 写需求规格，不被 AI 卡在 S1 要求补用户访谈 | `STD-REQ-01`、`00` S1、`T01`、`SKILL.md` | 路径明确 |
| 零经验成员启动新 Web 项目，不知道选什么后端和数据库 | 默认继承团队黄金技术栈（Vue 3 + Node.js Hono/Fastify + Prisma + SQLite/PostgreSQL），免写选型对比 ADR | `STD-ARC-09`、`T05`、`SKILL.md` | 路径明确 |
| AI 完成了工单接口与页面，成员看不懂 TypeScript 代码怎么验收 | AI 输出黑盒验真步骤：双无痕窗口测越权看 Network 是否返回 `404`、运行 `npx prisma studio` 看 `Ticket` 表字段、跑 `npm test` 看终端结果 | `STD-QA-12`、`06` 第 6.1 节、`03` 范本、`T07` | 路径明确 |
| AI 修改组件时引出连锁报错，连续两次没修好 | 触发 `STD-CODE-11` 救生规则，立即回退至上一小闭环的 Git 快照点，缩小修改范围重来 | `STD-CODE-11`、`06` 第 4.3 节、`T08` | 路径明确 |
| 涉及跨用户权限规则或准备上线发布（S8） | 黑盒自检通过后，触发 `STD-QA-12` 高风险门禁：发起独立上下文 AI 交叉审计会话或交由团队负责人复核签字 | `STD-QA-12`、`06` 第 6.1 节、`T12` | 路径明确 |
| 成员在 Antigravity 中只想改一个按钮间距（小变更路径） | 自动触发 Skill → 按 `stage-routing.md` 走小变更路径 → 只读 `T01` 与 `T06` 单文件（共 5KB）→ 继承既有风格修改并实际渲染对照 | `SKILL.md`、`stage-routing.md`、`templates/` | 路径明确 |
