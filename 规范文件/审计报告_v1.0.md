版本：1.0.0｜日期：2026-11-26｜性质：针对 v0.9.1 全面审计识别的 P0+P1 五项核心缺口（G-01 至 G-05）的工程化整改与端到端实测报告。修订前 `0.9.1` 基线已归档至 `../历史归档_勿喂给AI/2026-11-14_至_2026-11-26/v0.9.1-baseline.zip`。

## 1. P0 + P1 五项缺口闭环落实对照表

| 缺口编号 / 级别 | 0.9.1 审计发现的真实问题 | 1.0.0 整改交付资产与规则 | 端到端实测验证 |
|---|---|---|---|
| **G-01 / P0** | `contracts/base-contract.schema.ts` 直接导入 `node:crypto`，React + Vite 前端引用 Schema 会直接打包报错 | 拆分纯同构 `contracts/base-contract.schema.ts`（零 Node 依赖）+ 服务端专用 `contracts/fingerprint.server.ts`；Gate 2 新增前端禁引 `node:crypto` 扫描；更新 `STD-API-07/08` 与 `03` 案例 | 正向自检通过；负向测试在前端 `src/` 写入 `node:crypto` 被 Gate 2 拦截（退出码 `1`） |
| **G-02 / P1** | 缺少黄金栈一键初始化脚手架，新手与 AI 每次手配 `vite`/`tsconfig`/Preline/Prisma 极易踩坑 | 新增 `规范文件/starter/init-project.mjs` 与 9 份模板（含 `usePrelineInit.ts` 解决 Preline SPA 路由交互失灵、PostgreSQL 4 表底座与全部一键 npm 脚本） | 在空目录实测运行 `init-project.mjs --target <dir>` 一键生成 17 个标准文件并通过门禁 |
| **G-03 / P1** | Gate 1 只检查测试里有没有写 `@req/@ac`，未核对 `docs/` 里写的全部 `AC` 是否都被测试覆盖 | 升级 `ci/verify-gates.mjs` Gate 1：自动扫描 `docs/` 需求文档中的全部 `REQ-xxx` / `AC-xxx` 与 `tests/` 取差集，漏测或幽灵引用直接报错；同步 `STD-QA-13` | 负向测试在 `docs/T03.md` 新增未覆盖的 `AC-002` 时 Gate 1 精准报错 `漏测 AC: AC-002`（退出码 `1`） |
| **G-04 / P1** | 缺少统一认证、可吊销会话与 RBAC 权限代码底座，AI 易写出 `localStorage` 存令牌或弱哈希漏洞 | 新增 `STD-SEC-05`、`contracts/auth-rbac-baseline.md` 与 `starter/templates/auth-rbac.ts.tpl`（`scrypt` 随机盐、PostgreSQL 可吊销会话、`HttpOnly` Cookie、三层 RBAC 拦截）；Gate 2 扫描 `localStorage` 存令牌 | 负向测试在前端 `src/` 写入 `localStorage.setItem('auth_token', ...)` 被 Gate 2 拦截（退出码 `1`） |
| **G-05 / P1** | 缺少固定多角色测试种子与一键重置，新手每次做双无痕窗口黑盒验真都要手工注册造账号 | 新增 `STD-QA-14` 与 `starter/templates/seed.ts.tpl`（预置 `ADMIN`/`HANDLER`/`MEMBER_A`/`MEMBER_B` 4 个合成账号，内置 `NODE_ENV=production` 强熔断）及 `npm run db:seed` / `db:reset` | 脚手架成功生成 `prisma/seed.ts` 与一键命令，校验熔断守卫完整存在 |
