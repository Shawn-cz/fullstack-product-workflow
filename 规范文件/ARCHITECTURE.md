# 工作流体系结构

版本：0.8.0。本项目包含可跨平台使用的 Markdown 规范包，以及面向 Antigravity 等 AI IDE 的原生 `.agents/skills/fullstack-product-delivery/` 技能与根目录 `AGENTS.md` 规则入口。

## 信息分层

| 层 | 文件 / 目录 | 权威职责 |
|---|---|---|
| 自动触发入口 | `AGENTS.md`、`.agents/skills/fullstack-product-delivery/` | 在 AI IDE 中自动识别工作流纪律，按阶段路由读取单文件模板与规则，不另设冲突义务 |
| 导航 | `开始使用.md`、`规范文件/README.md` | 团队启动入口、黄金技术栈速览和当前交付边界 |
| 流程 | `规范文件/00_主流程.md` | 全栈执行顺序、三级裁剪、指令型需求豁免、工作目标和完成条件 |
| 规则 | `规范文件/01_规则库.md` | 112 条唯一规则 ID（`STD-*`）、触发条件、强制动作与验证要求 |
| 产物结构 | `规范文件/02_模板包.md` 及 `规范文件/templates/T01~T13` | 按阶段记录实际项目成果的字段结构；`templates/` 提供按需加载的独立单文件 |
| 案例参考 | `规范文件/03_贯穿案例_工单.md` | 展示需求、Prisma/Zod 机器契约与 T07/T12 黑盒证据填写格式，不是实际产品的权威规则 |
| AI 执行 | `规范文件/04_AI项目执行说明.md` | AI 读取、提问、代管 Git 快照、输出黑盒验真步骤与触发高风险独立复核的方式 |
| 演进 | `规范文件/05_来源与更新机制.md` | 46 组外部来源登记、候选修订、发布与迁移 |
| 质量应用 | `规范文件/06_工程质量与审计验收基线.md` | 架构/代码检查、零经验本地环境与 Git 救生（4.3 节）、黑盒可观察验真与高风险门禁（6.1 节） |
| 推进应用 | `规范文件/07_项目推进与多agent执行.md` | 增量、依赖、任务流转、并行开发与独立上下文交叉审计子 agent 说明 |
| 平台应用 | `规范文件/08_移动App专项.md` | 移动端黄金跨端栈（uni-app/Capacitor）与 MOB 规则执行说明，以 T13 汇总 |
| 维护 | `CHANGELOG`、`session_handoff`、`验证记录`、`审计报告_v0.8` | 当前版本变更、恢复上下文与真实检查结果 |
| 历史归档 | `历史归档_勿喂给AI/` | 物理隔离历史版本基线 zip、manifest、diff 及旧版审计报告，避免污染日常 AI 上下文 |

实际项目成果使用 REQ/RULE/API/UI/TEST 等项目 ID；本工作流规则使用 STD 前缀，来源使用 SRC，模板使用 T。它们不能混为一套编号。

## 渐进式上下文加载（Progressive Disclosure）设计

为解决零经验成员将 190KB+ 文档一次性塞给 AI 导致的注意力稀释问题，v0.8.0 采用三级渐进加载：
1. **常驻轻量规则（< 3KB）**：根目录 `AGENTS.md` 与 `SKILL.md` 仅声明核心纪律、黄金技术栈与阶段路由表。
2. **按阶段单模板加载（1–7KB）**：进入某阶段时，仅从 `规范文件/templates/` 读取对应的单个模板文件（如 S0 只读 `T01_项目启动与裁剪卡.md`）。
3. **历史归档物理隔离**：将占体积 80% 以上的历史 baseline 压缩包与 diff 移入顶层 `历史归档_勿喂给AI/`，与 `规范文件/` 解耦。

## 维护约束

规则新增或修改 → 同步检查相关阶段、汇总模板 `02_模板包.md`、独立模板 `templates/T*.md`、Skill 路由表、案例与来源 → 记录语义变化 → 运行哈希与断链校验脚本。删除规则时保留弃用说明，不复用旧编号表示不同含义。
