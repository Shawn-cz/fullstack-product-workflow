# 软件产品设计与全栈交付工作流 (v0.8.0)

## Overview

面向**零开发工作经验团队**的单人全栈产品设计与开发执行规范（S0–S9）。
**核心原则：** 成员负责业务决策与黑盒可观察验收；AI 负责契约落地、代码实现、Git 快照救生，并将所有技术验证转化为成员无需看代码即可亲自核实的黑盒操作。**违反规则字面要求即违反规则精神。**

## When to Use

- 启动新产品、新功能迭代、已有界面修改优化或缺陷修复
- 将模糊业务想法转化为需求（T03）、业务状态与权限（T04）、架构与契约（T05）、界面规格（T06）、实现与黑盒验收（T07/T12）

## 团队默认黄金技术栈（STD-ARC-09）

新建项目无既有仓库强约束时，**必须默认采用以下黄金技术栈**（无需每次重写选型对比 ADR；仅在硬约束无法满足时写 T05 ADR 并由团队负责人批准）：

| 层级 | 默认黄金技术栈 | 零经验成员黑盒验真配套 |
|---|---|---|
| **Web 前端** | Vue 3 (`<script setup lang="ts">`) + Vite + Tailwind CSS + Element Plus / Naive UI + Pinia | 浏览器实际渲染对照、`vue-tsc` |
| **后端与接口** | Node.js (LTS) + Hono / Fastify + TypeScript + Zod/TypeBox 校验 | 浏览器 F12 Network 状态码与响应 JSON 核对 |
| **数据库与 ORM** | Prisma ORM + SQLite（本地/单机）或 PostgreSQL（多用户生产） | 运行 `npx prisma studio` 在网页端可视化核对落库记录 |
| **移动 App** | uni-app (Vue 3 + TS) 或 Capacitor（复用 Vue 3 组件与契约） | 模拟器初筛 + 代表性真机核心链路实测 |
| **工程检查** | ESLint + Prettier + Vitest + Playwright（按需） | 单行命令 `npm run check && npm test` |

## 执行步骤与按需加载（Progressive Disclosure）

**禁止一次性加载全部模板或历史归档文件（`历史归档_勿喂给AI/`）。** 按当前阶段仅加载所需文件：

1. **先判路径与阶段**：读取 [stage-routing.md](./references/stage-routing.md) 或 [00_主流程.md](../../../规范文件/00_主流程.md)，判断属于**完整路径**、**功能路径**还是**小变更路径**，以及需求属于**探索型**还是**指令/契约型（STD-REQ-01，有负责人 DEC 直接进 S2，免外部访谈）**。
2. **按阶段只读单文件模板**：从 [规范文件/templates/](../../../规范文件/templates/) 读取当前阶段对应的 `T01`–`T13` 独立模板（1–7 KB），不要全量复制无关模板。
3. **查强制规则**：按阶段触发条件查阅 [01_规则库.md](../../../规范文件/01_规则库.md)；涉及代码与验收必读 [06_工程质量与审计验收基线.md](../../../规范文件/06_工程质量与审计验收基线.md)；移动端加读 [08_移动App专项.md](../../../规范文件/08_移动App专项.md)。
4. **改码前先做 Git 保存点（STD-CODE-11）**：在 S6–S7 动手改代码前，先运行 `git status`，确保工作区干净或创建快照保存点；每跑通一个最小闭环立即保存一次 Git 快照。若连续两次修复同一报错失败，立即协助成员回退至上一正常快照。
5. **输出黑盒可观察验真指南（STD-QA-12）**：完成代码后，除运行自动测试外，**必须输出 3–5 步零代码经验成员可亲自操作的黑盒验真清单**：
   - 打开哪个本地 URL 观察什么交互状态；
   - 如何开两个浏览器窗口（普通窗口 + 无痕窗口）登录不同角色测试越权（确认 Network 返回 `403`/`404` 而非仅前端隐藏按钮）；
   - 如何运行 `npx prisma studio` 查看哪张表新增/更新了什么字段值；
   - 复制运行哪条单行测试命令并看哪行通过提示。
6. **高风险独立复核门禁（STD-QA-12）**：触及 **D0/D1 权限与资金逻辑、破坏性数据迁移（STD-DAT-04）或 S8 生产发布** 时，必须发起**独立上下文交叉审计会话**（不共享开发上下文，仅凭契约审代码）或交由团队负责人签字确认。

## Rationalization Table（常见违规借口与反制）

| 常见借口 (Excuse) | 事实与强制处理 (Reality) |
|---|---|
| “这是内部指令需求，但 S1 要求用户访谈，先停下来让用户去访谈” | 违反 `STD-REQ-01`。负责人明确下达的指令型需求直接登记 `DEC` 进入 S2，不卡外部访谈。 |
| “这个小项目我用 React / Python / MongoDB 写更快” | 违反 `STD-ARC-09`。无既有仓库约束的新项目必须使用团队 Vue 3 + Node.js + Prisma 黄金栈，保证零经验团队可交接维护。 |
| “构建/单元测试绿了，视觉和功能就算验收通过” | 违反 `STD-QA-10` / `STD-QA-12`。构建通过 ≠ 视觉通过，Mock 通过 ≠ 真实落库通过；必须有真实渲染和黑盒查库证据。 |
| “我已经把代码 Diff 贴给成员看了，成员说没问题” | 违反 `STD-QA-12`。零经验成员看不懂底层代码漏洞，必须转化为浏览器/Network/`prisma studio` 黑盒验证步骤。 |
| “用户说优化一下这个页面，我顺便把整套配色和布局重做了” | 违反 `STD-FE-05`。修改已有界面默认继承既有风格与变量；仅在用户明确要求改版时按授权范围重做。 |

## Red Flags - STOP and Check

- 准备在未检查 `git status` 或未建快照点的情况下大面积改文件
- 准备一次性抛出 T01–T13 所有模板让用户像填问卷一样填写
- 发现权限/资金（D0）或 S8 发布未经过独立审计会话或负责人复核就要标“已验收”
- 在没有任何真实浏览器渲染证据的情况下将视觉验收标为“通过”

## 每轮结束标准汇报格式

> **当前阶段**：[S…｜路径：完整/功能/小变更]
> **本轮成果与 Git 快照**：[修改的文件路径｜当前快照 commit 哈希]
> **AI 已执行检查**：[运行的命令与真实结果]
> **请您执行的黑盒验真步骤（3 分钟）**：[1. 浏览器访问… 2. 双窗口越权检查… 3. `npx prisma studio` 核对…]
> **待决定/下一步**：[仅列影响业务结果或权限的必要问题，或下一具体动作]
